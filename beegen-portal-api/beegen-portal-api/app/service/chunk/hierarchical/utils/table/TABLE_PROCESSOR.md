# Table Processor - Architecture & Implementation Guide

## Overview

This document outlines the architecture for Processing Markdown tables into semantic text chunks within `table_processor.py`. The design utilizes Beeflow (`WorkflowEngine`) to efficiently route and process rows, splitting logic between deterministic parsing (simple tables) and sequential AI-driven batching (complex tables).

---

## Processing Architecture

```
markdown_text
    │
    ▼
detect_tables()  →  list[str] (all tables isolated)
    │
    ▼
table_processor.py (WorkflowEngine)
    │
    ├── classify_simple_table()
    │       │
    │       ├── True  → process_simple_table()
    │       │             - Row 1 = Column Names
    │       │             - Row 2 = Separator → skip
    │       │             - Row 3+ = Chunk row by row directly (No LLM, O(1) latency)
    │       │
    │       └── False → init_batch_state()
    │                     │
    │                     ▼
    │               WhileLoopNode (batch_loop)
    │                   - Split complex tables into chunks of N rows (e.g., N=5)
    │                   - Passes `context_summary` (active section, headers) iteratively
    │                   - Calls `qwen-instruct-chat` on each batch:
    │                       1. Generates Semantic Text Chunks directly.
    │                       2. Outputs updated context for the next iteration.
```

---

## Core System Decisions

### 1. Simple vs. Complex Tables
- **Simple Tables** are processed in milliseconds with raw Python logic since they have no merged cells.
- **Complex Tables** use an LLM batching loop. Complex tables are identified purely through the presence of `<merged>` prefix tags generated by the early stage `table_detector`.

### 2. The AI Batching Approach
Instead of writing complex, brittle Python state machines to detect Embedded Headers, Heading Trees, and `<merged>` cell deductions, we pass entire batches (e.g. 5 string markdown rows) to `qwen-instruct-chat`.
- The LLM natively understands markdown structure and deduces hierarchy, merging, and layout visually.
- To handle tables that exceed context windows or are excessively long, the table is processed in a `WhileLoopNode`.
- The `Context` state is summarized and passed from Iteration `i` to Iteration `i+1`.

---

## The Workflow Nodes in Complex Tables

Upon determining a table is Complex, the Workflow branches to:

1. **`init_batch_state`**:
   - Parses the `table_markdown` into batches of `5` rows.
   - Initializes the `[context_summary]` leveraging any `parent_heading` supplied from earlier pipelines.

2. **The `batch_loop` (`WhileLoopNode`)**:
   - Evaluates `check_continue`: if `iteration_count < batch_count`, it continues.
   - **`prepare_batch_prompt`**: Merges `[context_summary]` and `row_batches[iteration_count]` into an advanced system prompt. 
   - **`batch_llm`**: Invokes `qwen-instruct-chat` directly. Output is guaranteed valid JSON.
   - **`parse_batch_response`**: Parses the LLM's returned JSON object to extract `[extracted_chunks]` and `[updated_context_summary]`.
   - **`update_batch_state`**: Appends the extracted chunks to the `accumulated_chunks` array and sets `context_summary` = `updated_context_summary` for the next loop.

3. **`process_complex_result`**:
   - Exits the loop, consolidates `accumulated_chunks` into the final Workflow Output.

## The LLM Prompt Design

The batch LLM utilizes a comprehensive instructions prompt designed to bypass Python-level complexities:

**Instructions Provided to the AI:**
1. Generate cohesive semantic text chunks for EVERY data row in the given batch.
2. Maintain spatial awareness of the internal hierarchy: track the "Active Section" and "Active Column Headers" based on heading sub-rows or newly introduced nested grids.
3. Automatically interpret `<merged>` tokens as layout markers, eliminating duplicate text handling.
4. Output cleanly isolated Key-Value pairs combined with the active section label.

**Response Structure (JSON):**
```json
{
  "extracted_chunks": [
     "Hướng dẫn xử lý > ...\nTên cửa hàng: YODY\nSĐT: 090...",
     "..."
  ],
  "updated_context_summary": "Active Category: Hướng dẫn xử lý...\nActive Columns: Tên cửa hàng, SĐT, Địa chỉ"
}
```

## Migration History

*Legacy System (Pre-Batching):* The system originally relied on row-by-row deterministic Python processing containing over 6 branch nodes to classify strings as Headings, Column Headers, Data Rows, or Embedded Entities. This was retired in favor of the recursive Sequential AI Batch approach to handle malformed Markdown syntax flawlessly and to eliminate logic fragmentation.
